## Final history and responsive-chart addendum

The lead found a P2 state-consistency issue in the production browser: returning from a documentation page could restore range values after initial rendering, leaving results stale. **Resolved in source and lead-retested:** `pageshow` and `popstate` schedule `render` on the next animation frame. That render rereads the current controls and recomputes every displayed output through the existing engine; it neither replaces restored values with defaults nor introduces parallel calculations. The lead reports successful calculator-document/back cycles for combined, hotter, and historical-reference presets, with restored demand matching 86.84, 91.41, and 83.41 GW respectively. This reviewer verified the listener/render wiring and syntax, but did not independently repeat the browser navigation.

The SVG now derives its horizontal viewBox size from the chart's current width (minimum 240 units), retaining a 350-unit height and labeled margins, and redraws on window resize. Source inspection confirms that this changes display geometry only: all points still map from the same model outputs and fixed 0–4°C domain. It reduces mobile font scaling compared with the previous fixed 760-unit viewBox. Actual mobile readability and history behavior remain lead-owned rendered checks. `node --check src/app.js` passed after these edits. The independent scientific/source-level approval remains **passed**, with no new unresolved material issue.
